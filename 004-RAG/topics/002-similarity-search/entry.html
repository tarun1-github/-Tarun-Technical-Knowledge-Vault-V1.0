similarity search

Given a user's question, find the stored chunks whose meaning is most similar to the question.

Similarity search is the process of comparing a query embedding with stored document embeddings and retrieving the most semantically similar chunks.

User asks:

❓ "My Cisco phone is not registering. How can I fix it?"

The system first converts the question into an embedding:

Question

↓

Embedding Model

↓

[0.12, -0.04, 0.87, ... 3072 values]

Then it compares this vector against the vectors stored in the Vector DB.

========================================

One-line memory trick

Embedding = convert text → numbers

Similarity Search = compare numbers → find closest meaning

Cosine similarity tells us how similar two vectors are by measuring the angle between them.

Cosine Similarity

A · B

Cos(A,B) = ─────────────

‖A‖ × ‖B‖

If the angle θ is small, the vectors point in almost the same direction → high similarity.

If the angle is large → low similarity.

RAG = retrieve those closest chunks → give them to the LLM → generate answer.

But embeddings capture semantic meaning, so similarity search can recognize:

"phone isn't connecting"

≈

"endpoint registration failure"

That's why embeddings are powerful in RAG.
