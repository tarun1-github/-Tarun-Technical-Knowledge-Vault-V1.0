Docker BuildKit — Traditional vs Modern Docker Builds

Traditional Docker Build

│

├── Problem 1 → Packages re-download every build

│

├── Problem 2 → Secrets can leak into image/history

│

├── Problem 3 → Architecture lock-in

│

└── Problem 4 → Independent stages run sequentially

----------------------------------------------------------------------------------------

Problem 1 — Packages re-download every build

Consider dockerfile

FROM python:3.12

RUN pip install -r requirements.txt

COPY . .

If dependencies are downloaded during a build, rebuilding can cause unnecessary downloads.

Build 1

↓

Download Flask

Download LangChain

Download LangGraph

Download FastAPI

↓

Build

Build 2

↓

Download again ❌

This makes builds slower and wastes bandwidth.

Modern solution — Cache mounts

BuildKit allows a persistent cache to be mounted during the build.

Build 1

↓

Download packages

↓

Cache

Build 2

↓

Reuse cache ✅

↓

Only download what's missing
